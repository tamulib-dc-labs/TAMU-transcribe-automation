Oral History Transcription

Parakeet-TDT for words, Sortformer for speakers, fused on a shared time base. One Slurm submission does everything — nothing is staged from anywhere else.

190 tests 1 job, 4 tasks, 2×A100 each output schema unchanged

The flow

Everything below runs inside one sbatch. Compute nodes reach the network through HPRC's WebProxy, which is what removed every staging step.

Why these two models

Not just accuracy — they agree about time.

The alignment argument

Both models derive time from the same 16 kHz waveform through the same FastConformer frontend. Word timestamps and speaker turns therefore sit on one measured time base, and the fusion error is bounded by Sortformer's 80 ms frame grid.

A language-model diarizer writes its timestamps as generated text — it emits the characters [0.48] the way it emits any other token. Those times are predicted, nothing ties them to the audio, and joining them to measured word times gives speaker drift with no upper bound.

ModelProducesCost / 90 min
words parakeet-tdt-0.6b-v3 text, word start/end, per-word confidence ~1.6 s
turns diar_streaming_sortformer_4spk-v2.1 speaker spans, max 4 speakers ~11 s

Both ship in nemo_toolkit[asr], so they share one environment and one process. That single fact is why there is no split-worker architecture here.

What comes out

Real output from the code, not a mock-up. Same schema the WhisperX pipeline produced, so src/git/uploader.py and the reviewer app need no changes — speaker and source are new keys, additive.

On source

"measured" means the model produced that timing from the audio. "interpolated" means it was estimated because the model gave none — rare, but worth surfacing differently in review. There is no forced-alignment stage any more, so a word is either timed by the decoder or it is a guess, and the field says which.

Before the first real run

Does nemo_toolkit[asr] install on Grace? Both models come from that one package, so it is a single check.

Can a compute node reach the SMB share? WebProxy carries HTTP and HTTPS only; SMB is port 445 and does not go through it. The sheet and the Kaltura URLs are fine either way. If SMB is not reachable, stage the audio to scratch once and run with --source local — nothing else changes.

Nothing here has run on Grace yet. The queue protocol, fusion, output schema and worker loop are covered by 190 tests with the models stubbed; the two forward passes are not.
